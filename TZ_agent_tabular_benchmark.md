# ТЗ для автономного агента: Бенчмарк табличных foundation-моделей (TabPFN v2 / TabICL v2) против классики

## Роль и режим работы
Ты — автономный агент, работающий без пошагового участия человека. Двигайся по этапам 
последовательно, самостоятельно принимая решения там, где ниже не указано иное. 
Веди подробный лог (см. раздел "Отчётность") — это единственный способ для человека 
понять, что произошло, без пошагового наблюдения.

## Цель проекта
Провести объективный, воспроизводимый бенчмарк: насколько современные табличные 
foundation-модели (TabPFN v2, TabICL v2) реально превосходят или уступают классическим 
методам (XGBoost, CatBoost, RandomForest) на разнообразных, независимо выбранных 
табличных датасетах. Результат — не мнение, а таблица цифр с воспроизводимой методологией.

## Этап 1 — Подготовка окружения

1. Установить: `pip install tabpfn`, `pip install tabicl` (или клонировать 
   `github.com/soda-inria/tabicl`, если pip-пакета нет в момент выполнения — 
   проверить актуальный способ установки на странице репозитория), 
   `pip install xgboost catboost scikit-learn pandas numpy`
2. Зафиксировать версии всех библиотек в `requirements.txt` — это критично для 
   воспроизводимости
3. Проверить доступность GPU (`torch.cuda.is_available()`); если недоступен — 
   работать на CPU, но явно отметить это в отчёте, так как влияет на скорость

**Критерий завершения этапа:** все библиотеки импортируются без ошибок, версии 
зафиксированы в файле.

---

## Этап 2 — Выбор датасетов

Самостоятельно выбрать 6-8 табличных датасетов по следующим критериям 
разнообразия (не менее одного датасета на каждую категорию):
- Маленький датасет (< 1000 строк)
- Средний датасет (1000-50000 строк)
- Датасет с большим числом признаков (100+ колонок)
- Датасет с сильным дисбалансом классов
- Задача бинарной классификации
- Задача многоклассовой классификации (уложиться в лимиты моделей — уточнить 
  актуальные ограничения на числа классов в документации TabPFN v2 и TabICL v2 
  на момент выполнения)
- Задача регрессии

Источники: встроенные датасеты `sklearn.datasets`, открытые датасеты с Kaggle 
(через `kagglehub` или прямую загрузку публичных CSV), репозиторий OpenML 
(`openml.org`, есть Python-клиент `openml`).

**Критерий завершения этапа:** список из 6-8 датасетов с указанием источника, 
размера, числа признаков, типа задачи — сохранить в `datasets_manifest.json`.

---

## Этап 3 — Бенчмаркинг

Для каждого датасета:
1. Разбить на train/test (обычный 80/20 или time-based split, если в данных есть 
   временная компонента) с фиксированным random_state для воспроизводимости
2. Обучить и замерить: **XGBoost** и **CatBoost** с базовым, разумным подбором 
   гиперпараметров через `RandomizedSearchCV` или `Optuna` (не менее 20 итераций 
   перебора) — засечь общее время (подбор + финальное обучение)
3. Прогнать **TabPFN v2** и **TabICL v2** без всякой настройки гиперпараметров 
   (as-is, zero-shot) — засечь время (загрузка модели + inference)
4. Замерить на каждом: accuracy, F1 (для классификации) или RMSE/MAE (для регрессии), 
   ROC-AUC где применимо
5. Повторить каждый прогон 3 раза с разными random seed, усреднить результат — 
   учитывать вариативность, не полагаться на одно измерение

**Критерий завершения этапа:** таблица с результатами по всем моделям и датасетам, 
сохранённая как `benchmark_results.csv`.

---

## Этап 4 — Стресс-тест ограничений

Отдельно, на 2-3 подходящих датасетах из уже выбранных:
- Намеренно внести пропуски в данные (5%, 15%, 30% случайных значений) — сравнить 
  деградацию качества классики (с обычной импутацией) против foundation-моделей 
  (у них часто есть встроенная обработка пропусков — проверить и задокументировать)
- Урезать обучающую выборку до предельно малого размера (50-100 строк) — 
  посмотреть, где сильнее падает точность
- Если позволяет датасет — намеренно увеличить число классов ближе к 
  задокументированному лимиту модели, зафиксировать, где начинается деградация 
  или ошибка

**Критерий завершения этапа:** отдельный раздел в итоговом отчёте с графиками/таблицами 
деградации.

---

## Этап 5 — Итоговый отчёт

Собрать всё в единый Markdown-документ `FINAL_REPORT.md`, включающий:
1. Методологию (что и как тестировалось, версии библиотек, окружение)
2. Сводную таблицу по всем датасетам и моделям
3. Явные выводы: где foundation-модели выигрывают, где проигрывают, насколько 
   существенна разница (не только "лучше/хуже", но и на сколько процентных пунктов)
4. Сравнение по времени разработки/настройки (это отдельная, не менее важная 
   метрика, чем чистая точность)
5. Раздел "Ограничения этого исследования" — честно указать, что бенчмарк 
   не исчерпывающий, датасеты выбраны не случайно, а вручную
6. Атрибуцию использованных моделей согласно их лицензиям
